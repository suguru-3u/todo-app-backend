# Sessionについて
セッションとはサーバー側で保持するデータの保存のことです。
このセッションには、ユーザーのログイン情報などを保存することが多いです。

このセッションのデータを識別するためのセッションIDが存在します。
セッションIDはサーバー側で生成され、クライアントに渡されます。

クライアントは、セッションIDをcookieに保存し、以降のリクエストでサーバーに送信します。
※送信する際は自動で行ってくれる

# セキュリティ

セッションは重要なデータを保持しているので、セキュリティを気をつけないといけない。
セッションIDをクライアントに送信する際に設定を行うことでセキュリティを高めることができる。

## 設定項目

- HttpOnly 属性
この設定を行うことで、JavaScriptからクッキーにアクセスできなくなる。
これにより通常の通信の時だけセッションIDが送信されるようになる。

- Secure 属性
HTTPS通信の時だけセッションIDが送信されるようになる。
これにより、通信が暗号化されていない場合にセッションIDが盗まれるリスクを減らすことができる。

- SameSite 属性
これは「他のサイトから来たリクエストにクッキーを送信しない」設定です。
これにより、悪意あるサイトを開いたときに、勝手にあなたのブラウザから「銀行サイト」などへリクエストを送らされる攻撃<br>
クロスサイトリクエストフォージェリ（CSRF）攻撃を防ぐことができる。

- セッションIDの再発行
セッションIDを定期的に再発行することで、セッション固定化攻撃を防ぐことができる。
これは、攻撃者があらかじめセッションIDを知っている場合に、そのセッションIDを使って不正にログインする攻撃です。
ログイン時にセッションIDを再発行することで、攻撃者が知っているセッションIDが無効になるため、防ぐことができます。

- URLにセッションIDを含めない
  ?sid=xxx のようにURLでIDを渡せる設定（透過的セッションID）を無効にします。クッキーのみで管理する。

## タイムアウト
セッションでは、大きく分けて2つのタイムアウトが使い分けられています。

- アイドルタイムアウト
  一定時間操作が行われなかった場合にセッションを無効化する。
  例：30分間操作がなければログアウト
  仕組み： サーバーにアクセスがあるたびに「最終アクセス時刻」を更新し、そこから例えば「30分間」アクセスがなければ鍵（セッション）を破棄します。
  例： ネットバンキングなど

- 絶対タイムアウト
  セッションが作成されてから一定時間が経過した場合にセッションを無効化する。
  例：ログインしてから8時間経過したらログアウト
  仕組み： 「ログインした瞬間」を基準にし、そこから例えば「24時間」経過したら無効にします。
  例： SNSや業務アプリ

また有効期限（Expires/Max-Age）を設定しているとしていないで、クッキーが消えるタイミングが変わります。
① ブラウザを閉じたら消える（セッションクッキー）
クッキーに有効期限（Expires/Max-Age）を設定しない場合、そのクッキーはブラウザのメモリ上にだけ保存されます。ブラウザを完全に閉じると鍵が消える。

② ブラウザを閉じても残る（持続的クッキー）
「ログイン状態を保持する」にチェックを入れた場合などがこれです。クッキーに「1週間」などの期限を書き込むため、ブラウザを閉じてもパソコン内に鍵が残り続けます。

##  ログアウト時の挙動
ログアウト時には、サーバー側でセッションを無効化し、クライアント側のクッキーも削除する必要があります。
- サーバー側
  サーバー側では、セッションを無効化するために、セッションIDに対応するデータを削除します。
- クライアント側
  クライアント側では、クッキーを削除するために、クッキーの有効期限を過去に設定します。
  ブラウザは有効期限が過ぎているクッキーを即座に削除するため、ブラウザはクッキーを削除します。
